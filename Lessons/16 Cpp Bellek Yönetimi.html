Bellek Yönetimi

Bellek Yönetimi Nedir?

Bellek yönetimi, yazılım program tarafından kontrol edilmeyen ve kontrolu tamamiyle programcıda olduğu veri yapılarının yönetiminidir.
Bellek yani RAM'de bir programcılar olarak özel alanlar istiyebiliriz. Normal şartlarda bellek yönetimi program tarafından yapılır. Program kapsama adı verilen ve bizim kod blokları adını veridiğimiz küme parantezlerinde({ ... }) tanımlanan yerel değişkenleri programın kendisi yönetir. Değişken tanımlandığı kod blokları içerisinde aktiflik gösterir taki program akışı değişkenin kod bloklarının sonuna geldiğinde değişkeni serbest yani RAM'e geri verir. Bu durumu bilgisayar özelinden anlatırsak biz programcı olarak değişkenimizi tanımlarken RAM'e "Şu kadar alanda bana yer aç" diye bir komut veriyoruz. RAM'de eğer yer varsa uygun alanı açıyor ve bize erişim sağlıyor ki o erişim bizim değişkenimiz oluyor. Daha sonra o erişim yani değişken üzerine kendimize özel RAM'den tahsis ettirdiğimiz alanda işlemlerimizi gerçekleştiriyoruz. Ardından program o değişkenin kod bloklarının sonuna geldiğinde RAM'e gidip "Bu değişkenle işim bitti. Dolayısıyla bu alan sana geri veriyorum" der ve değişkenimizi RAM geri alır. Bu durum bir nevi ödünç alma ilişkisidir. İhtiyacımız olduğunda RAM'den ödünçlük yer isteriz. RAM verdiği ödünçlük alanda istediğimizi yaparız ve ardından ödünç aldığımız alanı RAM'e geri teslim ederiz. Bu olaylar programcıdan ziyade program tarafında yapılır. Biz sadece tanımlar kullanılır ve geçeriz. Gelin bir örnek yazalım;
#include <iostream>

using namespace std;

int main()
{

    int sayi1 = 12; // Örnek bir sayı tanımladık

    { // Kod blokları içerisinde başka kod blokları açabiliriz.
        cout << "sayi1 = " << sayi1 << endl << endl; // Üst kod bloklarında tanımlanan değişkeni bu kısımda kullanabiliriz

        int sayi2 = 54; // Şimdi bu kod blokları içerisinde bir değişken tanımlayalım
        
        cout << "sayi2 = " << sayi2 << endl << endl; // Ardından kullanalım
    } // sayi2 değişkeninin serbest bırakıldığı yani RAM'e geri verildiği kısım

    cout << "sayi1 = " << sayi1 << endl << endl; // Hala aynı kod blokları içerisinde olduğumuz için sayi1 değişkenini kullanabiliriz
    
    //cout << "sayi2 = " << sayi2 << endl << endl;
    // Fakat sayi2 değişkeni kendi kod bloklarında serbest bırakıldığı için başka kod bloklarında kullanılamaz

    return 0;
}

Çıktısı ise;
Görüceğiniz üzere yerel değişkenler program tarafından yönetilir.
Peki ya biz yönetseydik? Bazı durumlar olucak ve bizim o kod bloklarının içinden başka kod bloklarına veri aktarmamız gerek durumlar elbette olucaktır. İşte bu durumlarda bellek yönetimi devreye gidiyor... Bellek yönetimi asasen programcı tarafından yönetilen bellek demek. Yani değişken tanımlarken biz talimat vericeğiz ve biz yer ayırttıp boşaltacağız. Bu işlemleri ise new ve delete komutları ile gerçekleştiriceğiz. Ayrıca bellek yönetimi direkt olarak işaretçilerden yürür. Bu sebeble Pointerlar konusunda eksiğiniz bulmaması önemle rica olunur. Gelin bir örnek daha yaplım;
#include <iostream>

using namespace std;

int main()
{
    int *sayi2Ptr; // Şimdilik tanımlayalım. 2. kod bloğunda new ile alan açıcağımızda bu değişkene atıcağız. Yoksa program olarak mümkün değil kod blokları arasında veri iletişimi. İşte bu yüzden Pointer'lar bizim en yakın dostumuzdur

    int *sayi1Ptr = new int; // sayi1Ptr adlı bir işaretçi tanımlıyoruz ve new komutu ile RAM'den bir Integer'lık alan talep ediyoruz. New eğer başarılı olursa bize ayrdığı belleğin adresini döndürür. Başarısız olursa bize nullptr döndürür
    if (sayi1Ptr == nullptr) // Eğer başaramazza. Genelde RAM çok dolu olduğunda bellek ayrılma işlemi doğal olarak başarısız olur ve bize new nullptr döndürür. Daha önceki sayfalarda konuştuğumuz gibi nullptr bir felakete yol açmadan hemen önce fark edilip programın durdurulması veya doğru yönetilmesi gerekir
    {
        cout << "Bellek ayrilamadi" << endl; // Hata mesajı

        delete sayi1Ptr; // Ayıramadığı için serbest bırakalım
    }

    // Başarılı bir şekilde ayrılırsa

    *sayi1Ptr = 12; // Atama gerçekleştirelim
    
    { // Başka bir kod bloğu açalım
        cout << "sayi1Ptr = " << sayi1Ptr << " -> " << *sayi1Ptr << endl << endl; // Hem bellek adresini hemde bellek adresindeki veriyi yazdıralım

        sayi2Ptr = new int(56); // Şimdi new ile sayi2Ptr'yi RAM'de özel alan ayırtalım. Eğer parantezlere bir değer yazarsak, new başarılı olursa direkt atama gerçekleştirir
        if (sayi2Ptr == nullptr) // Kontrol
        {
            cout << "Bellek ayrilamadi" << endl; // Hata mesajı

            delete sayi2Ptr; // Ayıramadığı için serbest bırakalım
        }

        cout << "sayi2Ptr = " << sayi2Ptr << " -> " << *sayi2Ptr << endl << endl;
    } // new ile ayrdığımız için değişken bu kısımda RAM'e geri verilmez

    cout << "sayi1Ptr = " << sayi1Ptr << " -> " << *sayi1Ptr << endl << endl;
    // Şimdi ikisini beraber bu kod bloklarında kullanabiliriz
    cout << "sayi2Ptr = " << sayi2Ptr << " -> " << *sayi2Ptr << endl << endl;

    delete sayi1Ptr; // Ardından RAM'den ödünç aldığımız alanları RAM'e geri veriyoruz
    delete sayi2Ptr; // ki program bellek hatalarıyla ve sızmalarla karşılaşmasın. Bu tüm new ile ayrılan veriler için geçerlidir

    return 0;
}

Çıktısı;
Artık istediğimiz gibi kullanabiliriz...
İşte bellek yönetimi tamda budur. Bellek yönetimi programcıya mutlak güç verir. Pek tabi büyük güç büyük sorumluluk gerektirir. Eğer gücü kullanıp sorumluluğu yerine getirmezsek RAM'ın gazabına uğrarız. RAM'den ödünç alınan her alan ne olursa olsun program kapanmadın geri verilmelidir. Yoksa RAM gereksiz yere şişer ve o belleklere erişemez hale geliriz. Buda RAM'de eve işgal edip kira dahi ödemeyen bir misafir olur. Bu misafir günümüzde pek önemsemesede eskiden RAM'ler dolayısıyla evler küçüktü. Bu zamanki RAM'leri eski RAM'lerle karşılaştırıcaksak bizim RAM'lerde eskilere göre koca bir megakent. Eski RAM'ler bir nevi küçük bir köy gibi kalıyor. Nasıl Megakentlerde kira vermeyen oturan insanlar önemsemiyorsa şimdiki zamanlarda aynı şekilde bu serbest bırakılmayan RAM alanlarıda aynı şekilde önemsemiyor. Keza eskiden bu durum tam bir baş belasıydı. Ama eğer şimdi o davetsiz misafirlerle ilgilenmezsek yarın bir gün onlar bizi misafir hatta evsiz bile bırakabilir.... Dikkatli olmakla fayda var.

RAM'in Katmanları

RAM'ın belirli başlı katmanlara sahiptir. Bu katmanlar farklı amaçlar doğrultusunda kullanılır. Gelin beraber incelemek için bir görsel gösterelim;

Yazı Katmanı(Text Segment)

Yazı katmanı, programlarımızın derlenmiş hallerinin RAM'de saklandığı kısımdır.
Bu katman salt okunur olarak kullanılır. Yani okunabilir fakat yazılamaz. Bu önemlin amacı canlı olarak çalışan programın içeriğini değiştirilmesini önlemektir. Yani evet programlar sanılınanın aksine SSD veya HDD'de değil RAM'in kendi içindeki yazı katmanında çalışırlar.

Veri Katmanı(Data Segment)

Veri katmanı programda tanımlanan değişkenlerin saklandığı kısımdır.
Tanımlanan değişkenler şekillerine göre bu katmanın alanları olan başlatılmış ve BSS yani başlatılmamış alanlara yazılır. Başlatılmış değişkenler tanımlandığı an itibariyle değeri atanan değişkenlerdir. BSS yani başlatılmamış değişkenler ise tanımlandığı anda tanımlanmayan değişkenlere denir. Gelin bir örnek yapalım;
#include <iostream>

using namespace std;

int main()
{
    int BSS_Degisken; // Veri katmanındaki BSS alanında depolanır

    int baslatilmisDegisken = 23; // Veri katmanındaki başlatılmış alanında depolanır

    cout << "BSS_Degisken = " << BSS_Degisken << endl << endl; // Eğer BSS değişkenlere başlatılmadan erişilmeye çalışınılırsa derleme zamanında rastgele bir değer atanan değeri verir
    cout << "baslatilmisDegisken = " << baslatilmisDegisken << endl << endl;

    return 0;
}
        
Çıktı;

Heap Katmanı(Heap Segment)

Heap katmanında boyutu belli olmayan, programcı tarafından ayrılan değişkenler ve işaretçiler bu katmanda yer alır. Yani bu değişken

int *sayi1Ptr;

Bu katmanda yer alır.

Stack Katmanı(Stack Segment)

Stack katmanı ise boyutu belli olan ve önceden tanımlı veriler yer alır. Yani bu değişken

int sayi1 = 32;

Bu katmanda yer alır.

Segmentation Fault

Segmentation Fault veya katman hatası, bir bellek alanına izinsiz giriş veya nullptr olarak tanımlanan bir işaretçinin bellek adresine erişim çalışmasında gerçekleşen ve programın çökmesiyle sonuçlanan bir hatadır. Gelin bir örnek yazalım;
#include <iostream>

using namespace std;

int main()
{
    int *sayi1Ptr = nullptr; // Bir işaretçiyi kasten nullptr olarak tanımlandık

    cout << "sayi1Ptr = " << *sayi1Ptr << endl << endl; // Erişmeye çalışma ve bam... Program çöker

    return 0;
}

Program sonuç olarak çöker.

New ve Delete Komutları

Sayfanın başında değindiğimiz new ve delete komutlarına değinelim. Bu komutlar bizim bellek yönetimimizde en temel araçlarımızdır. new ile yer ayırtır, delete ile de ayrılan alanları RAM'e geri verilir.
Bir örnek yazalım.

#include <iostream>

using namespace std;

int main()
{
    int *sayi1Ptr = new int(10);

    cout << "sayi1Ptr = " << sayi1Ptr << " -> " << *sayi1Ptr << endl;

    delete sayi1Ptr;

    return 0;
}

Çıktısı bellek adresi ile "10" olucaktır.
Karşılaştırma açısından birde C programlama dilinde az önce yazdığımız kodun karşılığını yazalım;

#include <stdio.h>
#include <stdlib.h>

int main()
{
    int *sayi1Ptr = (int*)malloc(1 * sizeof(int)); // -> new

    *sayi1Ptr = 10;

    printf("%x -> %d\n", sayi1Ptr, *sayi1Ptr);

    free(sayi1Ptr); // -> delete

    return 0;
}


Çıktı aynı olucaktır.
Çıktılar ve amaçlar aynı olsada kullanılan yöntemler birbirinden tamamiyle farklıdır.
C++ programlama dilinde malloc ve free kullanılabilir fakat standartlar doğrultusunda tavsiye edilmez. Çünkü malloc;
  • Dönüş olarak void* gibi bir işaretçi değer döndürür. Bu durum tür güvenliğini tehlikeye atar. Bu sebeble dönüştürme işlemi yapılır.
  • Başarısız olursa NULL döndürür ki NULL bir nevi sıfır demektir.
  • Tahsis edilmesi gereken alan bayt cinsinden belirtilmelidir. Bu sebeble "1 * sizeof(int)" kolaylık açısından yazılır.
  • Dizi tanımlamak için herhangi bir yardımcı yoktur.
Gibi sebeblerden dolayı modern C++ kodlarında malloc kullanılmaz. new'i ele alıcaksak eğer;
  • Dönüş tipi olarak, tanımlanan türün işaretçisini döndürür. Ekstra dönüştürmeye gerek yoktur.
  • Başarısız olursa nullptr döndürür.
  • Tahsil edilmesi gereken alanın belirtilmesine gerek yoktur.
  • Dizi tanımlamak için yardımıcısı bulunur.
Gibi nedenlerde dolayı new C++ programlama dilinde bellek yönetimi için birer standarttır.

Dizi Tanımlama

Tekli veriler tanımlayabiliyoruz da dizi neden tanımlayamamalım? new tur[elemanSayisi] şeklinde dizi tanımlanır ve delete[] ile serbest bırakılır.
Gelin bir örnek yapalım;

#include <iostream>

using namespace std;

int main()
{
    int *sayilar = new int[4]; // 4 elemanlı bir dizi tanımladık

    *sayilar = 10; // Değerler atadık
    *(sayilar + 1) = 20;
    *(sayilar + 2) = 30;
    *(sayilar + 3) = 40;

    cout << "sayilar dizisinin elemanlari;" << endl; // Bellek adresleriyle yazdırdık
    for (int i = 0; i < 4; i++)
    {
        cout << &sayilar[i] << " -> " << *(sayilar + i) << endl;
    }
    cout << endl;

    delete[] sayilar; // Serbest bıraktır

    return 0;
}

Çıktı;

Akıllı İşaretçiler ile Bellek Yönetimi

Akıllı işaretçilerle bellek yönetimi sıklıkla kullanılırlar. Örnek olması açısından akıllı işaretçiler konusundaki unique_ptr'i bellek yöntemiyle beraber yazalım;
#include <iostream>
#include <memory>

using namespace std;

class ornekClass
{
    public:
        int *s;

        ornekClass()
        {
            s = new int;
        }
        ~ornekClass()
        {
            delete s;
        }
};

int main()
{
    unique_ptr<ornekClass> sayi1 = unique_ptr<ornekClass>(new ornekClass()); // İçini new ile değiştirdik
    *sayi1->s = 123; // Değer atadık

    cout << "sayi1'deki s'in degeri; " << *sayi1->s << endl << endl;

    //ornekClass* sayi2 = sayi1; Bu tarz bir kullanıma izin vermez
    unique_ptr<ornekClass> sayi2 = move(sayi1); // Taşıma ile verileri aktardık
    cout << "sayi2'deki s'in degeri; " << *sayi2->s << endl << endl;

    return 0;
}

Çıktısı ise fakat yöntemi farklıdır.

Placement New

Placement New yani belirli alanda New işlemi, new komutunun bir kullanım tarafıdır. new parantezlerine belirtilen bellek alanında istenilen bellek tahsisin gerçekleştiren bir yöntemdir.
Gelin bir örnek yapalım;

#include <iostream>

using namespace std;

int main()
{
    char *belirliBirAlan = new char[8]; // 8 baytlık bir alan tahsis ettik

    int *sayi1 = new(belirliBirAlan) int(100); // 4 baytlık alanın 1. 4 baytlık alanına bir Integer tanımladık ardından 100 değerini atadık

    float *ondalikli1 = new(belirliBirAlan + 4) float(50.5f); // Aynı şekilde bir Float tanımladık. belirliBirAlan'a 4 ekledik çünkü Integer'ın için ayırdığımız bölgeyi işgal etmesin

    // Ardından hepsini yazdıralım
    cout << "sayi1 = " << sayi1 << " -> " << *sayi1 << endl;
    cout << "ondalikli1 = " << ondalikli1 << " -> " << *ondalikli1 << endl;

    delete belirliBirAlan; // Delete işleminde ana alan faz alınır

    return 0;
}
