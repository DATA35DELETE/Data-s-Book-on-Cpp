Dosya İşlemleri

Dosya İşlemleri Nedir?

Dosya işlemleri, dosyalar üzerinde yapılan işlemlere; Oluşturma, değiştirme veya kaldırmaya eylemlerine denir.
Peki neden dosya işlemlerine ihtiyaç duyarız? Bunun sebebi kalıcı veri ihtiyacıdır. Biz bu zamanda kadar hep RAM üzerinde verilerimizi depoladık. Yeri geldi program tarafından verilen alanı kullandık yeri geldi kod blokların verilerimizi silmesine karşın kendi alanlarımızı ayırdık. Fakat bu işlemler hep geçicidir. Evet RAM çok hızlı ama bir kadarda geçicidir. İşte dosya işlemleri ve SSD/HDD bu kısımda yardımıza koşarlar! Dosya işlemleri SSD/HDD üzerinde kalıcı veri saklamamızı sağlar. RAM bildiğiniz gibi bilgisayar kapandığı an RAM'in içi boşalır. Yani tüm alanlar RAM'e ait olur. RAM'i burada cimri bir arkadaş gibi düşünebilirsiniz. Ödünç aldığınız eşyaları işinizi bitirir bitirmez hemen elinizden alırlar. RAM'de işte bu arkadaş gibidir. Tüm sistem kapandığı an alanların hepsi RAM'e ait olur. Ama SSD/HDD öyle değildir. Dosya işlemleri sayesinde SSD/HDD üzerinde kendi özel kalıcı alanlarımızı oluşturabilir ve işlemlerimizi gerçekleştirebiliriz. Genelde de oyunlar oyuncuların ayarlarını kaydetmek için dosyalar kullanılırlar çünkü dosyalar teorik olarak bilgisayar kapanıp on bin yılın ardından açılsa bile silinmez veya zarar görmezler.

Fstream Kütüphanesi

Fstream kütüphanesi C++ programlama dilinin dosya işlemleri için yazılmış kütüphanesidir. üç adet dosya işlemleri için sınıfı vardır: Ifstream, Ofstream ve Fstream'dir.

Ifstream Sınıfı

Ifstream, Fstream kütüphanesindeki dosyaları okumak için kullanılan bir sınıftır.
Hadi gelin bir örnek yapalım. Tahim edebiliyorum ki bu dökümantasyonun öncesi olan Data's Book on C dökümantasyonumu okuyanlar pek yoktur. Ama okuyanlar için bu kodlar bir yerlerden tanıdık gelicektir;
        
İlk olarak okuyacağımız olan dosyayı hem kendimiz oluşturmalı hemde içini doldurmalıyız. İlerleyen satırlarda bunun programama yaptırtacağız. Fakat önce biz

main.txt adlı bir dosya oluşturalım ve içerisine;

#include <stdio.h>

int main(){
    FILE* file = fopen("dosyaIsmi.dosyaUzantisi", "w"); // Klasörde bulunmayan bir dosya oluşturuyoruz. w, dosya yoksa oluşturma yeteneğine sahiptir

    fclose(file); // Bellek yönetimi için gereklidir

    return 0;
}

Ardından main.cpp kod dosyamızı bu kodlar ile dolduralım;

#include <iostream>
#include <fstream> // Kütüphanemiz

using namespace std;

int main()
{
    ifstream dosya1("main.txt"); // Dosya okuma nesnemiz
    string satir; // Okumada kullanılan satir değişkeni

    while (getline(dosya1, satir)) // Getline, verilen dosya nesnedeki her bir satırı sırayla 2. parametredeki string ifadesine atar
    {
        cout << satir << endl; // Alınan satırları yazdırma
    }
    
    dosya1.close(); // Serbest bırakma. Bellek yönetimi için gereklidir

    return 0;
}

Aynı dinamik bellek açarken gibi dosya işlemlerinde de işimiz bittiğinde .close() ile dosyayı serbest bırakırız.

Ofstream

Ofstream, C++ programlama dilindeki Fstream kütüphanesindeki yazma işlemleri için kullanılan bir sınıftır.
Şimdi Ifstream ve Ofstream'in başka bir farkı ise Ofstream olmayan bir dosyayı oluşturabiliyor olmasıdır. Bu özellik ile bir örnek daha yapalım. Bir önceki örnekte bir dosyayın içerisindeki veriyi konsola yazdırmıştık. Bu sefer o dosyadaki verileri ilk olarak ekrana daha sonra bir dosyaya son olarak da o dosyadaki verileri ekrana yazdıralım;

#include <iostream>
#include <fstream>

using namespace std;

int main()
{
    ofstream yazma("main.c"); // Yazılıcak dolayısıyla yazılıcak olan dosya

    ifstream okuma("main.txt"); // Okunucak dosya
    string satir; // Satır için string değişken

    cout << "main.txt dosyasinin icerigi;" << endl;
    while (getline(okuma, satir))
    {
        yazma << satir << endl; // Tıpkı Cout gibi kaydırma işlemi ile dosyalar yazılabilir
        cout << satir << endl; // Aynı zamanda konsola yazdırma
    }
    cout << endl;

    okuma.close(); // Okuma nesnemizi serbest bıraktık
    yazma.close(); // Yazma nesnemizi serbest bıraktık

    okuma = ifstream("main.c"); // Aynı okuma nesnemize başka bir dosya okuması için görev verdik. Bellek yönetimi için sıkça kullanılır

    cout << "main.c dosyasinin icerigi;" << endl;
    while (getline(okuma, satir))
    {
        cout << satir << endl;
    }
    
    okuma.close(); // Tekrardan serbest bıraktık

    return 0;
}

Fstream

Fstream, Fstream kütüphanesinin ana dosya işlemleri sınıfıdır.
Fstream, hem okuma hemde yazma yeteneklerine sahip bir dosya işlemleri nesnedir. Bu sebeble C++ yazılımcıları genelde Fstream kullanılırlar. Bu mod geçişini ise "mod" denilen ve bir nevi yetki verme parametreleri ile yapılır.

Gelin bir önceki örneği Fstream ile yeniden yazalım;

#include <iostream>
#include <fstream>

using namespace std;

int main()
{
    fstream hedefDosya("main.c", ios::in | ios::out);

    fstream kaynakDosya("main.txt", ios::in); // Kaynak dosyamız. Okuma modunda
    string satir;

    cout << "main.txt dosyanin icerigi;" << endl;
    while (getline(kaynakDosya, satir))
    {
        cout << satir << endl;
        hedefDosya << satir << endl;
    }
    cout << endl;

    kaynakDosya.close(); // Kaynak dosya ile işimiz bitti
    hedefDosya.seekg(0); // Dosya konumlandırma yapıyoruz ki okuma işleminde tüm dosyayı okuyalım

    cout << "main.c dosyanin icerigi;" << endl;
    while (getline(hedefDosya, satir))
    {
        cout << satir << endl;
    }
    cout << endl;

    hedefDosya.close(); // Hedef dosyamızı serbest bıraktık
}

Dosya Modları

Dosya modları kodlarken de gördüğümüz yetkilendirme elemanlarıdır. ios kütüphanesinde bulunur ve bit işlemlerimde kullandığımız uzun çizgi(|) ile modlar birleştirilir.
Gelin tablo şeklinde inceleyelim;
İsim Açıklaması
ios::in Dosyadan veri alabilmemizi sağlar.
ios::out Dosyadan veri yazabilmemizi sağlar. Eğer dosya yoksa oluşturur, mevcut ise üzerine yazar.

Dosya İşlem Noktasını Konumlandırma

Dosya işlem noktası, dosya nesnelerinde işlemlerin kaçıncı harfinde yapıldığını belirten bir konum bilgisidir. Her işlem sonucudan dosya işlem noktası yapılan işlem kadar harf karf kaydılır. Bu bilgiyi değiştirebilir veya alabiliriz.
dosyaNesnesi.seekg(int x); // x bayt kadar okuma işleminin dosya işlem noktasını konumlandırır
dosyaNesnesi.seekp(int x); // x bayt kadar yazma işleminin dosya işlem noktasını konumlandırır
dosyaNesnesi.seekg(0, ios::end); // Okuma işleminin dosya işlem noktasını, dosyanın en sonuna konumlandırır
dosyaNesnesi.seekp(0, ios::end); // Yazma işleminin dosya işlem noktasını, dosyanın en sonuna konumlandırır

unsigned long long okumaKonum = dosyaNesnesi.tellg(); // Yazma işleminin dosya işlem noktasının konumunu verir
unsigned long long okumaKonum = dosyaNesnesi.tellp(); // Okuma işleminin dosya işlem noktasının konumunu verir
Peki harf biz harf mi sayıcağız bu noktayı konumlandırmak için? Tabiki hayır! Harf dediğim şey aslında sekiz bitlik olan karakterler yani bayt bilgisidir. Atıyorum dosya işlem noktası yüzüncü harfte ise yüzüncü baytta olduğunu anlarız veya yüzüncü baytta olması için yüz bayt ileri atarız dosya işlem noktasını... Ayrıca Türkçe karakterlerinde içerisinde bulunuğu UTF-8 karakterleri iki bayt olarak sayılır.
Hadi gelin bir main.c dosyasını sadece yarısına kadar okuyalım!

#include <iostream>
#include <fstream>

using namespace std;

int main()
{
    fstream mainDotC("main.c", ios::in | ios::out); // main.c dosyamız için nesmemiz

    mainDotC.seekg(0, ios::end); // Seekg ile dosyadaki dosya işlem noktasını dosyanın en sonuna geitrdik

    cout << "main.c dosyasinin toplam karakterlerin sayisi; " << mainDotC.tellg() << endl << endl; // Ardından tellg ile de dosyanın dosya işlem noktasının bilgisini aldık. Bu karakterlerin sayısı vericektir

    mainDotC.seekg(mainDotC.tellg() / 2); // mevcut konumu ikiye bölerek dosyanın yarısına dosya işlem noktasını konumlandırdık

    // Şimdi okuyabiliriz
    string satir;
    cout << "main.c dosyasinin yarisi;" << endl;
    while (getline(mainDotC, satir))
    {
        cout << satir << endl;
    }
    
    mainDotC.close();

    return 0;
}

İkili(Binary) İşlemleri

İkili işlemler, dosya işlemlerinde en düşük seviyeli işlemlerdir. İkili işlemler yapılırken Binary dosyaları ".dat" uzantısı ile kayıt edilir.
İkili işlemler farklı bir işlem yapalım. Şimdi biz işaretçiler sayesinde tüm nesnelerin kaynak kodlarına istersek erişebiliyoruz. Erişebiliyorsak bir dosyayada yazabiliriz demektir. O zaman bir sınıf oluşturalım ve o sınıftan oluşturulmuş nesnemizin kaynak kodunu bir .dat dosyasına yazalım. Daha sonra başka bir programda o dosyayı okuyalım ve içi boş olan başka bir nesneyi o veri ile dolduralım;

yazici.cpp
#include <iostream>
#include <fstream>

using namespace std;

class birSinif // Sınıfımız
{
    public:
        char charDizisiVerisi[100] = "birSinif'in char dizisi degeri"; // String nesnesi gönderemeyiz çünkü bu sistem low-level olduğu için OOP desteklemez. İlkel veri yapılarını destekler
        int s1 = 123;
        float f1 = 33.5f;
};

int main()
{
    birSinif nesne; // Bir nesne oluşturalım

    fstream birSinifKaynakDosyasi("birSinif.dat", ios::out | ios::binary); // İkili kaynak kod dosyamızın nesnesi
    birSinifKaynakDosyasi.write((char*)&nesne, sizeof(birSinif)); // İkili olarak yazmamızı sağlayan fonksiyon
    // (char*)&nesne; Bu kısımda aslında oluşturulan nesninin bellek adresini alıyoruz. Daha sonra write bizden bir char işaretçisi istediği için C tarzı dönüşterme ile bir nesnemizin kaynak kodunu bir char dizisiymiş gibi görür
    // sizeof(birSinif); Yazdırılıcak olan verinin boyutu.

    birSinifKaynakDosyasi.close(); // Dosyamızı serbest bıraktık
}

Yazıcı bizim için sınıfın kaynak kodunu yazıcak.

alici.cpp
#include <iostream>
#include <fstream>

#include <string.h> // memset için gerekli

using namespace std;

class birSinif // Okunucak olan sınıfın içi doldurulmamış hali. Buna ihtiyaç vardır çünkü veriler iletilir ama hangi verinin kime ait olduğu yani işaretçi gönderilmez. Bu tarz yapılara "Gövdesiz yapı" denir
{
    public:
        char charDizisiVerisi[100];
        int s1;
        float f1;
};

int main()
{
    birSinif *nesne = new birSinif(); // Bir nesne oluşturalım
    memset(nesne, 0, sizeof(birSinif)); // Nesnenin içini boşaltıyoruz ki yazdırıcağımız veriler için yer olsun

    fstream birSinifKaynakDosyasi("birSinif.dat", ios::in | ios::binary); // İkili kaynak kod dosyamızın nesnesi
    birSinifKaynakDosyasi.read((char*)nesne, sizeof(birSinif)); // Read ise ikili verileri okuyan bir fonksiyondur
    // (char*)nesne; Normalde bizden bir Char işaretçisi ister ama biz write'da olduğu gibi manüpile ederek bizim kendi nesnemize yazdırmasını sağlıyoruz
    // sizeof(birSinif); Okunucak alan

    birSinifKaynakDosyasi.close(); // Dosyamızı serbest bıraktık

    // Verilemiz geldi şimdi yazdıralım
    cout << "Aktarilan siniftaki charDizisiVerisi: " << nesne->charDizisiVerisi << endl;
    cout << "Aktarilan siniftaki s1: " << nesne->s1 << endl;
    cout << "Aktarilan siniftaki f1: " << nesne->f1 << endl;

    delete nesne; // Dinamik olarak ayrdığımız için serbest bıraktık
}

Filesystem

Filesystem, C++ programalama dilinde dosyalar üzerinde daha fazla kontrol sağlamamızı ve klasör işlemleri için kolaylık sağlayan bir kütüphanedir. C++17 ile standartlanlaştırılmıştır. filesystem kütüphane dosyasında yer alır.

Dosya Varlık Kontrolü

Filesystem kütüphanesinde bulunan path sınıfıyla tanımlanan dosya yolunda herhangi bir veri olup olmadığını kontrolü ile varlık kontrolu yapılır.
Hadi gelin bir örnek yapalım;
        
#include <iostream>
#include <filesystem> // Kütüphanemiz

using namespace std;

int main()
{
    filesystem::path aliciDotCpp = "alici.cpp"; // String tanımlar gibi Path sınıfı tanımlayabiliriz

    cout << "alici.cpp klasorde mevcut mu; ";
    if (filesystem::exists(aliciDotCpp))
    // filesystem::exists fonksiyonu filesystem kütüphanesindeki varlık kontrolu için kullanılır
    {
        cout << "evet";
    }
    else
    {
        cout << "hayir";
    }
    cout << endl << endl;

    // Birde olmayan bir dosyayı kontrol edelim(Makarayız ya abi)

    aliciDotCpp = "alici.c"; // Başka bir dosya yolu tanımlayabiliriz

    cout << "alici.c klasorde mevcut mu; ";
    if (filesystem::exists(aliciDotCpp))
    {
        cout << "evet";
    }
    else
    {
        cout << "hayir";
    }
    cout << endl << endl;
    
    // Son olarak klasör kontorlu yapalım
    cout << "../DBoCpp klasoru mevcut mu; ";
    filesystem::path denemeDizini = "../DBoCpp";
    if (filesystem::exists(denemeDizini))
    {
        cout << "evet";
    }
    else
    {
        cout << "hayir";
    }
    cout << endl << endl;

    return 0;
}

Filesystem ile Dosya Yönetimi

Filesystem, Path ile dosyaları kopyalabilir, yeniden adlandırabilir veya taşınabilir yapan fonksiyonlar sağlar.
Hadi bir örnek daha yapalım;

#include <iostream>
#include <fstream>
#include <filesystem>

using namespace std;

int main()
{
    // Kopyalama
    filesystem::path kaynakDosya = "yazici.cpp"; // Hedef dosyamız
    filesystem::path hedefDosya = "yazici.txt"; // Kaynok dosyamız veya yolumuz

    filesystem::copy(kaynakDosya, hedefDosya); // Dosya kopyalamamızı sağlar

    ifstream hedefDosyaNesnesi(hedefDosya); // Dosya nesnemiz
    string satir;
    
    cout << "yazici.txt dosyasinin icerigi;" << endl;
    while (getline(hedefDosyaNesnesi,satir))
    {
        cout << satir << endl;
    }
    cout << endl;

    hedefDosyaNesnesi.close();

    // Yeniden adlandırma
    filesystem::rename(hedefDosya, "writer.cpp"); // Dosyaları yeniden adlandırmamızı sağlar
    // hedefDosya; Orjinal dosyanın ismi
    // "writer.cpp"; Değiştirlmek istenen isim

    hedefDosyaNesnesi.open("writer.cpp"); // Tekrar okuyalım
    cout << "writer.cpp dosyasinin icerigi;" << endl;
    while (getline(hedefDosyaNesnesi,satir))
    {
        cout << satir << endl;
    }
    cout << endl;

    hedefDosyaNesnesi.close();

    // Silme
    filesystem::remove("writer.cpp"); // Dosya yolu ile dosya siler

    cout << "writer.cpp dosyasi mevcut mu; ";
    if (filesystem::exists("writer.cpp")) // Dosya varlık kontrolu
    {
        cout << "evet";
    }
    else
    {
        cout << "hayir";
    }
    cout << endl;

    return 0;
}

Klasör İşlemleri

Klasör işlemleri, C programalam dilinde işletim sisteminde özgüydü ve kodlaması bir hayli uğraştırıcıydı. C++ programala dilinde Filesystem sayesinde bu işlemler platformanlar arası bir hal aldılar.
Hadi klasörleri işliyelim;

#include <iostream>
#include <filesystem>

using namespace std;

int main()
{
    filesystem::path bilgilerim = "bilgilerim"; // Klasör yolumuz

    filesystem::create_directory(bilgilerim); // Klasörü oluşturduk

    cout << "bilgilerim klasoru mevcut mu; ";
    if (filesystem::exists(bilgilerim))
    {
        cout << "evet";
    }
    else
    {
        cout << "hayir";
    }
    cout << endl;

    filesystem::copy(".", bilgilerim); // Bulunduğumuz klasörün içeriğini bilgilerim klasörüne kopyalayalım

    return 0;
}

Klasörlerin İçeriğini Yazdırma ve Dosyaların Bilgilerini Yazdırma

Klasörlerin içeriğini yazdırmak için Range tabanlı For ile elemanlar arasında geçişler yapılır.
Hadi bir örnek daha yapalım;

#include <iostream>
#include <filesystem>

#include <format> // Tarih için gerekli olan format fonksiyonunu bulunduran kütüphane
#include <chrono> // Zaman damgası formatı için gerekli kütüphane

using namespace std;

int main()
{
    filesystem::path bilgilerim = "bilgilerim"; // Klasör yolumuz

    cout << "bilgilerim klasorunun icerigi;" << endl;
    for (auto i : filesystem::directory_iterator(bilgilerim))
    // Bir klasör iteratörü ile Range tabanlı For ile her bir dosya teker teker nesne olarak i değişkenine atanır
    {
        cout << i.path() << ":" << endl // Elemanın yolunu alma
            << "\tboyutu: " << i.file_size() << " b" << endl // Elemanın boyutu
            << "\tDosya mi: " << i.is_regular_file() << endl // Eleman bir dosya mı
            << "\tKlasor mu: " << i.is_directory() << endl // Eleman bir klasör mü
            << "\tYazilma Damgasi: " << i.last_write_time().time_since_epoch().count() << endl // Elemanın Unix Zaman damgası ile yazılma vakti
            << "\tYazilma Tarihigi: " << format("{}", i.last_write_time()) << endl; // Formatlı bir şekilde yazıma
    }
    cout << endl;

    filesystem::remove_all(bilgilerim); // Klasörün içeriğini silme
    filesystem::remove(bilgilerim); // Klasörü silme

    return 0;
}

Native Dosyalar

Native dosyalar, kendi içerisinde çalıştırabilir kodları bulunduran fakat Main fonksiyonu bulunmayan dosyalardır.
Yani bir nevi çalıştırılabilir kodları barındıran bir depo gibi çalışır. Siz o Native dosyasını kendi programınızda açarsınız veya uygun fonksiyonları tanımlarsınız. Ardından programınız o Native dosyasındaki fonksiyonları çağırabilir hale gelir. Native dosya aslında her yerdedir. ".dll" veya ".so" uzantılı dosyalar Native bir nevi kütüphane olarak kullanılır.
Peki Native dosyalara neden ihtiyaç duyarız? Çünkü esneklik ve kod yönetimi! Esneklik sağlar çünkü ana programlama fonksiyonları birbirinde ayırır. Kod yönetimi sağlar çünkü kodları ayrı ayrı değerlendiririz ve gereken kısımları işlemlerimizi gerçekleştiririz. Native dosyasız bir programı geliştirirken, geliştirmede bütün kodlar incelenir. Native dosyalar bu durumda özellikle büyük projelerde zaman ve yönetim için sıklıkla kullanılır.
Native dosyalar yapısı gereği platfrom bağımlıdır. Bu sebeble her Native dosya derlendiği platforma özgüdür. Ayrıca iki türdür. Dinamik ve statik olarka ikiye ayrılırlar.

Linux İşletim Sisteminde Native Dosya Yapımı

Native dosyaların uzantısı ".so" ve ".a" uzantılarına sahiptir.
".so" dosyası dinamik Native dosyası türüne aittir. Dinamik Native dosyaları sadece çalışma zamanında, çalışan programın algılayabilceği bir klasörde yer aldığı sürece çalışan ve işlemler gerçekleştirebilceğimiz bir türdür. Dinamik olarak derlenen Native dosyalar ana programla fonksiyonları dosya şeklinde ayırırlar. Ayrıca ana program boyutundan tasaruf edilmiş olur. Hadi gelin bir tane dinamik derliyelim ve uygulayalım;

İlk olarak dinamik Native dosya olucak olan kodları yazalım.

Amacımız bu konuda bir (klişe olucak ama...) hesap makinesi olsun. Toplama, çıkarma, bölme ve çarpma için fonksiyonları bir dinamik Native dosyası aracığıyla ana programda kullanalım. İlk olarak dinamik dosyanın kaynak kodlarını yazalım;

mat.cpp

// Native dosyalarda, ana programa fonksiyonları tanımlamak için "extern" ifadesi kullanılır. Extern, fonksiyonları Native fonksiyonları ana programdaki tanımlı fonksiyonlara tanımlar
extern int topla(int x, int y)
{
    return x + y;
}

extern int cikar(int x, int y)
{
    return x - y;
}

extern int bol(int x, int y)
{
    return x / y;
}

extern int carp(int x, int y)
{
    return x * y;
}

Kodlarımız hazır. Şimdi kodlarımızı derliyelim. Bir tık farklı olucak ama şuanki derleme işlemi bağlamasız olucak. Yani kodlar sadece derlenmiş hallerini yapıcağız.

g++ -c -fPIC mat.cpp

Oluşan dosya "mat.o" adlı bir sadece derlenmiş bir dosyadır. Şimdi o derlenmiş dosyayı Native dosya haline getirelim.

g++ -shared mat.o -o libmat.so

Tebrikler! Artık "libmat.so" adlı bir dinamik Native dosyamız oldu. Native dosya yaparken çıktının isimlerinin her zaman başında "lib" yazılması mühimdir. G++ kuralları gereği yapmak zorundayız.

Şimdi ana programımızı yazalım;
main.cpp

#include <iostream>

using namespace std;

extern int topla(int x, int y);
extern int cikar(int x, int y);
extern int bol(int x, int y);
extern int carp(int x, int y);
// Native dosyamızdaki fonksiyonların imzalarını yazdık

int main()
{
    cout << "3 + 2 = " << topla(3, 2) << endl << endl; // Fonksiyonlarımızı sırayla kullandık

    cout << "5 - 1 = " << cikar(5, 1) << endl << endl;

    cout << "1 * 10 = " << carp(1, 10) << endl << endl;

    cout << "7 / 7 = " << bol(7, 7) << endl << endl;

    return 0;
}

Kodlar hazır. Şimdi az önce oluşturduğumuz dinamik Native dosyasını ana programımız ile derliyelim;

g++ main.cpp -o main -L. -lmat
-L.; Native dosyalarının nerede olduğunu ayarlamamızı sağlayan bir parametre
-lmat; libmat.so Native dosyamızı bağlar. "l" ifadesi "lib"e tekabul geldiği için ve bu kural olduğu için kütüphane yaparken dosyanın başına "lib" ifadesi konulur.

Programımız derledik fakat çalıştıramayız. Linux Dünya'sı oluşturulduğu anda itibariyle dosya sistemi dolayısıyla kütüphane bulma sistemi ağaç benzeri bir yapıdır. Kütüphaneler "/lib" klasöründe bulunur. İstersek kütüphanemizi o klasöre taşıyarak programızın çalışmasını sağlayabiliriz. Ama bu bir test olduğu için ve Linux kolay bozulabildiği için ufak bir terminal üzerinden değişken ayarlıyarak bu durumu çözebiliriz. Değişken sisteme; "Kütüphaneleri bir de kendi klasöründe ara" der.

export export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH

Artık programız çalışabilir halde!

Çıktısı;
Eğer dilersek bu kütüphane dizinini ayarlama işini kod tarafında yapabiliriz "Sembol Çözümleme" denilen ve dinamik Native dosyaların içerisindeki fonksiyonları kod tarafında erişebiliyoruz. Bu özelliği Linux'daki #include <dlfcn.h> kütüphanesindeki dlopen, dlsym ve dlclose ile yapılır.
            
Bu mantık ise "Sembol" mantığı ile yapılır. Biz fark etmesekte programlarımız ve Native dosyalarımız aslında birer sembol tablosu gibidir ki bir kod editörü ile bir çalıştırabilir dosyaları açmaya çalıştığınızda anlamsız semboller görürsünüz. Onlar bizim için bir anlam ifade etmez lakin bilgisayar için "Program Kullanım Klavuzu" gibi çalışır. Bilgisayar bu program için hangi kütüphaneleri getirceğini hangi fonksiyon hangi bellek adresine gibi hayati önem taşıyan bilgileri bu sembol mantığı ile çözer. İlk olarak çözüceğimiz olan sembolleri Native dosyadan bulalım. "Nm" komutu bizlere sembolleri gösteren bir araçtır;

nm libmat.so

Çıktısı;
Fark etti iseniz çıktısının en sonunda bizim tanımladığımız fonksiyonları isimleri yer almaktadır. Ekstra harfleri saymazsak o bizim tanımladığımız fonksiyonları ifade eder. Fakat sizlerde farklı bir şekilde gözükebilir, dikkat edelim. Şimdi bu sembol isimlerini ana programda kullanarak çağrıcağız!
        
#include <iostream>
#include <dlfcn.h> // Evet kendisi bir C kütüphanesidir

using namespace std;

int (*topla)(int x, int y); // Fonksiyonlarımızı işaretçi olarak tanımladık
int (*cikar)(int x, int y);
int (*bol)(int x, int y);
int (*carp)(int x, int y);

int main()
{
    void* matKutup = dlopen("./libmat.so", RTLD_LAZY); // Dinamik Native dosyası açtık.
    // "./libmat.so"; Açılacak olan dosyanın ismi
    // RTLD_LAZY; Modu. Fazla RAM yemesin diye LAZY yani "Çağrıldığında Çalış" dedik

    *(void **)(&topla) = dlsym(matKutup, "_Z5toplaii"); // dlsym; Native dosyadan sembol çözümler ve o sembolün bellek adresini döndürür
    // C kütüphaneleri C'e göre kodlandığı için ve C++'da C'e kıyasla fazla esnek olmadığı için böyle bir söz dizimi ortaya çıktı. Sırayla açıklayalım
    // *(void **)(&topla); Bu kısımdaki olay dönüştürmedir. Bu kısımda dlsym'in döndüğü void* verisini fonksiyona uyucak şekilde dönüştürdük
    // matKutup; Çözümlenecek olan Native dosyanın objesi
    // "_Z5toplaii"; Çözümlenmesi gereken sembol

    // Aynı işlemi diğerleri içinde yaptık

    *(void **)(&cikar) = dlsym(matKutup, "_Z5cikarii");
    *(void **)(&bol) = dlsym(matKutup, "_Z3bolii");
    *(void **)(&carp) = dlsym(matKutup, "_Z4carpii");

    cout << "3 + 2 = " << (*topla)(3, 2) << endl << endl; // Fonksiyonlarımızı sırayla kullandık

    cout << "5 - 1 = " << cikar(5, 1) << endl << endl;

    cout << "1 * 10 = " << carp(1, 10) << endl << endl;

    cout << "7 / 7 = " << bol(7, 7) << endl << endl;

    dlclose(matKutup); // Bellek yönetimi için serbest bıraktık

    return 0;
}

Şimdi ise sembol çözümleme ile ana programandan kütüphane fonksiyonlarını çekelim. Windows'da diğer her işlem gibi bu işlemde #include <windows.h> kütüphane ile yapılır.

main.cpp
#include <iostream>
#include <windows.h>

using namespace std;

int (*topla)(int, int);
int (*cikar)(int, int);
int (*bol)(int, int);
int (*carp)(int, int);

int main()
{
    HMODULE matKutup = LoadLibraryA("./libmat.dll"); // dlopen karşılığı

    topla = (int (*)(int, int))GetProcAddress(matKutup, "_Z5toplaii"); // dlsym karşılığı
    cikar = (int (*)(int, int))GetProcAddress(matKutup, "_Z5cikarii");
    bol = (int (*)(int, int))GetProcAddress(matKutup, "_Z3bolii");
    carp = (int (*)(int, int))GetProcAddress(matKutup, "_Z4carpii");

    cout << "3 + 2 = " << topla(3, 2) << endl << endl; // Fonksiyonlarımızı sırayla kullandık

    cout << "5 - 1 = " << cikar(5, 1) << endl << endl;

    cout << "1 * 10 = " << carp(1, 10) << endl << endl;

    cout << "7 / 7 = " << bol(7, 7) << endl << endl;

    FreeLibrary(matKutup); // dlclose karşılığı

    return 0;
}

Json Dosyaları

Json, verileri Json formatlı ile beraber dosyalara serilizasyonla aktarmamızı ve kullanmamızı sağlayan özel bir formattır. Json dosyaları ".json" uzantısına sahiptir.

Json Mantığı

Json mantığı aslında çok basittir. Dizi veya değişken tanımlamalar ile veriler çekilir veya yazılır. Üstedelik sözdizimi oldukça basittir. Genellikle toplu veri kayıt etme gibi işlemlerde sıklıkla kullanılır. Ayrıca herhangi bir Native dosyaya ihtiyaç duymaz. Tüm kodlar tek bir kütüphane dosyasında toplanmıştır. Taşınabilirliği maksimumdur.

nlohmann Kütüphanesinin Kurulumu

C++ programlama dilinde sade ve öz bir Json dosyalarını yönetme kütüphanesi sunar.
Windows;
pacman -S mingw-w64-x86_64-nlohmann-json

Linux;
sudo apt install nlohmann-json3-dev

Json Kullanımı

 Json dosyalar ile bir "bilgiler" sistemi yapalım;

#include <iostream>
#include <fstream>
#include <nlohmann/json.hpp> // Kütüphaneyi ekliyoruz

using namespace std;

int main()
{
    nlohmann::json verilerim; // verilerim adlı bir json objesi oluşturduk

    // Verilerimizi tanımlayalım
    verilerim["Isim"] = "Data"; // nlohmann kütüphanesi Json objelerine veri gönderirken tıpkı bir Map STL koyteynırına veri atıyormuş gibi veri göndermemizi sağlar
    verilerim["Soyisim"] = "Delete"; // Ki Json mantığıda bir nevi Map mantığına benzer
    verilerim["Yasim"] = 15; // Sayı da atıyabiliriz
    verilerim["En sevdigim sayi"] = 3.14f;
    verilerim["Adresim"]["Turkiye"] = "Izmir"; // Şeklinde Json dizi verebiliriz
    verilerim["Becerilerim"] = {"C", "C++", "Java"}; // Şeklinde C++ diziside tanımlamak mümkün

    // Verilerimiz tamam şimdi bu yapıyı bir String'e dönüştürelim ki dosya yazmak daha kolay olsun

    string verilerimStr = verilerim.dump(); // .dump() ile Json objesi bir String ifadeye dönüştürdük

    std::ofstream bilgilerimDotJson("bilgilerim.json"); // Json verisinin bir dosyaya yazdıralım

    bilgilerimDotJson << verilerimStr; // Yazdırık

    bilgilerimDotJson.close();

    /* bilgilerim.json dosyasının içeriği;
    {
    "Adresim":
    {
        "Turkiye":"Izmir"
    },
    "Becerilerim":["C","C++","Java"],
    "En sevdigim sayi":3.140000104904175,
    "Isim":"Data",
    "Soyisim":"Delete",
    "Yasim":15
}*/

    // Şimdi yazdırdığımız bilgilerim.json dosyasını okuyalım

    ifstream bilgilerimDotJsonOkuma("bilgilerim.json"); // Dosya nesnemiz

    nlohmann::json bilgilerimiOkuma = nlohmann::json::parse(bilgilerimDotJsonOkuma); // Parse komutu ile yazdığımız veriler Json objesine dönüştü

    bilgilerimDotJsonOkuma.close();

    // Verileri okuyalım

    cout << "Bilgilerim;" << endl;
    cout << "Isim: " << verilerim["Isim"] << endl;
    cout << "Soyisim: " << verilerim["Soyisim"] << endl;
    cout << "Yasim: " << verilerim["Yasim"] << endl;
    cout << "En sevdigim sayi: " << verilerim["En sevdigim sayi"] << endl;
    cout << "Ev Adresim: " << verilerim["Adresim"]["Turkiye"] << endl;
    cout << "Becerilerim: " << verilerim["Becerilerim"] << endl;

    return 0;
}

Xml Dosyaları

Xml dosyaları, hem insanlar hemde bilgi tabanlı sistemlerde kolaylıkla veri alış-alışverişini sağlayan bir standarttır. W3C(World Wide Web Consortium) tarafından 1996 yılında yayımlanmıştır.

Xml Mantığı

Xml, tıpkı Json gibi verileri belirli bir formatta depolamamızı veya paylaşabilmemizi sağlayan, etiket ve özellik denilen özellikleriyle veri saklıyan bir dosya formatıdır.
Json'dan daha gelişmiştir. Genellikle Json'dan daha karmaşık işlerde kullanılır. Örneğin bir bir verinin ismini etiketler içerisinde yazılır iken, özellikler ile daha fazla bilgiyi tutabilir.

Xml Dosyası Kullanımı

Json dosyalarındaki örneğimizi Xml'de tekrar yazalım;
        
#include <iostream>
#include <fstream>
#include "pugixml.hpp" // Kütüphanemizi 

using namespace std;

int main()
{
    pugi::xml_document bilgilerimXml; // Xml nesnesini oluşturduk
    
    pugi::xml_node ismim = bilgilerimXml.append_child("ismim"); // Etiket ekleme için append_child kullanılır. Parantezlerindeki String değeri etiketin ismi olur. Bu fonksiyon bizlere dönüş olarak etiketin objesini döndürür. Böylelikle daha fazla kontrole sahip oluruz
    ismim.append_child(pugi::node_pcdata).set_value("Data"); // Etikete değer eklemek için set_value yazılır
    
    pugi::xml_node soyismim = bilgilerimXml.append_child("soyismim");
    soyismim.append_child(pugi::node_pcdata).set_value("Delete");
    soyismim.append_attribute("Yas") = 15; // Etiketlere özellik eklemek için append_attribute kullanılır. Parantezlerdeki String ifadesi özelliğin ismi, eşittirin solundaki değer ise özelliğe atanacak değerdir

    pugi::xml_node kisiselBilgilerim = bilgilerimXml.append_child("kisiselBilgilerim");
    pugi::xml_node kisiselBilgilerimEnSevdigimSayi = kisiselBilgilerim.append_child("enSevidigimSayi"); // Etiketlerin içerisine etiket eklemek
    kisiselBilgilerimEnSevdigimSayi.append_child(pugi::node_pcdata).set_value("3.14");

    pugi::xml_node kisiselBilgilerimEnSevdigimRenk = kisiselBilgilerim.append_child(pugi::node_pcdata).append_child("enSevdigimRenk");
    kisiselBilgilerim.remove_child("enSevdigimRenk"); // Etiketleri silmek için

    pugi::xml_node becerilerim = kisiselBilgilerim.append_child("becerilerim");

    pugi::xml_node becerilerim1 = becerilerim.append_child("C");
    pugi::xml_node becerilerim2 = becerilerim.append_child("Cpp");
    pugi::xml_node becerilerim3 = becerilerim.append_child("Java");

    bilgilerimXml.save_file("bilgilerim.xml"); // Kayıt edilen Xml verilerini bir dosyaya yazdırmak için kullanılır

/* Klasörde oluşan bilgilerim.xml dosyasının içeriği;

<?xml version="1.0"?>
<ismim>Data</ismim>
<soyismim Yas="15">Delete</soyismim>
<kisiselBilgilerim>

Zstandart ile Sıkıştırılmış Dosyalar

Zstandart veya kısaca zstd, Facebook tarafından 2015 yılında geliştirmiş ve veri sıkıştırmak için kullanılan bir C kütüphanesidir. Zstandart ile sıkıştırılan dosyaların uzantısı ".zst" uzantısıdır.
Zstd, genel olarak diğer sıkıştırma araçlarına nazaran(Rar, zip veya gzip gibi) çok daha hızlı ve performanslı bir şekilde sıkıştırma sağlayan, yaklaşık 100 mb/s kadar sıkıştırma ve 400 mb/s kadarda açma hızı sağlar.

Kurulum

Windows;

pacman -S mingw-w64-x86_64-zstd

Linux;

sudo apt install libzstd-dev

Kullanım

Şimdi ise "bilgilerim.xml" dosyasını Zstd ile sıkıştıralım, ardından sıkıştırılan veriyi tekrar açalım.

İlk olarak sıkıştırıcı programın kaynak kodu;
compresser.cpp

#include <iostream>
#include <fstream>

#include <zstd.h> // Zstd kütüphanemiz

using namespace std;

int main()
{
    ifstream bilgilerimDotXml("bilgilerim.xml"); // bilgilerim.xml dosyamızın nesnesi
    string kaynakVeri = ""; // bilgilerim.xml dosyasının verisi

    string *satir = new string(); // Bellek yönetimi için RAM'den alan telap ettik
    while(getline(bilgilerimDotXml, *satir)) // Okuma
    { 
        kaynakVeri += *satir + "\n"; // Okuduğumuz verileri kayıt ediyoruz
    }
    delete satir;
    bilgilerimDotXml.close();

    unsigned long long kaynakBoyutu = kaynakVeri.size() + 1; // Kaynağın yani sıkıştırılacak olan verinin boyutunu aldık. Bir attırdık çünkü String boyutu hesaplarken sondaki "\0" saymaz. Zstd'da C tabanlı olduğu için ve Zstd'da String ifadelerde her zaman sonda "\0" olduğu için verinin sonuna 1 ekliyerek yer açmış oluruz

    size_t hedefBoyutu = ZSTD_compressBound(kaynakBoyutu); // Hedef verinin yani sıkıştırılmış verinin kayıt edilceği miktardır. Mantıksal olarak sıkıştırılan veri kaynaktan az olduğundan kaynak verinin boyutu kadar yer kaplıyabilir. ZSTD_compressBound boyutu 64 değerini ekliyerek en zorlu sıkıştırmalarda bile sorunsuz geçmesini sağlar

    char hedefVeri[hedefBoyutu]; // Sıkıştırılacak olan verinin kayıt edilceği alan.

    size_t compresSize = ZSTD_compress(hedefVeri, hedefBoyutu, kaynakVeri.c_str(), kaynakBoyutu, 19); // Sıkıştırma fonksiyonu. Dönüş olarak sıkıştırılmış olan verinin boyutunu döner
    // hedefVeri; Sıkıştırılmış verinin işaretçi ile alanı
    // hedefBoyutu; Sıkıştırılmış verinin yazılma miktarı
    // kaynakVeri.c_str(); Sıkıştırılacak olan verinin başlangıç işaretçisi
    // kaynakBoyutu; Sıkıştırılacak olan verinin boyutu
    // 19; Sıkıştırma seviyesi. Maksimum 19 iken minimum 1'dir. Seviye ne kadar düşükse o kadar sıkıştırma performansı düşük fakat sıkıştırma hızı yüksektir. Seviye ne kadar yüksekse o kadar sıkıştırma performansı yüksek fakat sıkıştırma hızı düşüktür

    ofstream bilgilerimDotZst("bilgilerim.zst"); // Sıkıştırılmış verinin kayıt edilceği dosya nesnesi

    for (size_t i = 0; i < compresSize; i++) // For ile kayıt edilir. Çünkü sıkıştırılmış veriler bolca Null yani "\0" içererir. C++ programlama dilindeki yazma fonksiyonları; "Null görene kadar yaz" şeklinde çalıştığı için verimiz yarım kalabilir
    {
        bilgilerimDotZst << hedefVeri[i]; // Kayıt ettik
    }
    
    bilgilerimDotZst.close();

    return 0;
}

Ardından sıkıştırılmış dosyayı açan programın kaynak kodları;
decompresser.cpp

#include <iostream>
#include <fstream>

#include <zstd.h>

using namespace std;

int main()
{
    ifstream bilgilerimDotZst("bilgilerim.zst"); // bilgilerim.zst dosyamızın nesnesi
    string kaynakVeri = ""; // bilgilerim.zst dosyasının verisi

    string *satir = new string; // Bellek yönetimi için RAM'den alan telap ettik
    while(getline(bilgilerimDotZst, *satir)) // Okuma
    { 
        kaynakVeri += *satir + "\n"; // Okuduğumuz verileri kayıt ediyoruz
    }
    delete satir;
    bilgilerimDotZst.close();
    
    unsigned long long kaynakBoyutu = kaynakVeri.size() + 1;
    
    unsigned long long hedefBoyutu = ZSTD_getFrameContentSize(kaynakVeri.c_str(), kaynakVeri.size() + 1); // Hedefin boyutunu yani açılacak olan verinin açılmış halinin boyutunu verir
    char hedefVeri[hedefBoyutu]; // Açılmış verinin kayıt edilceği alan

    ZSTD_decompress(hedefVeri, hedefBoyutu, kaynakVeri.c_str(), kaynakBoyutu); // Sıkıştırılan verilerin tekrar açılmasını sağlayan fonksiyondur
    // hedefVeri; Açılmış verinin işaretçi ile alanı
    // hedefBoyutu; Açılmış verinin yazılma miktarı
    // kaynakVeri.c_str(); Açılacak olan verinin başlangıç işaretçisi
    // kaynakBoyutu; Açılacak olan verinin boyutu

    for (size_t i = 0; i < hedefBoyutu; i++) // For ile yazdırıyoruz. Çünkü sıkıştırılmış veriler bolca Null yani "\0" içererir. C++ programlama dilindeki yazma fonksiyonları; "Null görene kadar yaz" şeklinde çalıştığı için verimiz yarım kalabilir
    {
        cout << hedefVeri[i]; // Yazdırdık
    }

    return 0;
}
