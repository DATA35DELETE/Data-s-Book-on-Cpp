Test Sistemi

Test Nedir?

Test, yazdığımız kodları otomatik bir sistem tarafında bütün olasılıkları deniyen ve bir hata çıktıysa bize bildiren bir sistemdir.
Peki neden test etmeliyiz veya neden sadece kendimiz test etmiyoruzda bu işi algoritmalara bırakıyoruz? Cevap basit, otonatikleştirmek. Düşünün, bir sistem içerisinde yüzden fazla fonksiyon var ve bu fonksiyonları cağırıp çıktılarını değerlendirmek açıkcası acı verici olur. Çünkü çok zaman alırdı. İşte test sistemleri bu işi sadece "İşlemi gir, ne beklediğini yaz" prensibiyle bizim yerimize girdiğimiz bütün çıktıları analiz eder ve bir rapor verir.

Unit Test Nedir?

Unit Test, yazılım sistemlerinde test edilebilir en küçük parçalara denir. Genelde bir fonksiyon, yapı veya sınıf test edilen kısımlara Unit Test yani birim testi denir.

Google Test

Google Test veya gTest, C++ için geliştirilmiş popüler bir test kütüphanesidir.

Kurulum

Windows; pacman -S mingw-w64-x86_64-gtest

Linux; sudo apt install libgtest-dev

CMake;
find_package(GTest REQUIRED)
add_executable(uygulamaAdi main.cpp)
target_link_libraries(uygulamaAdi GTest::gtest GTest::gtest_main)

Kullanımı

Kütüphanemiz kurulduğuna göre basit bir örnek yapalım. Bir hesaplama makinesi kodlayalım ve gTest ile test edelim;

#include <iostream>
#include <gtest/gtest.h> //gTest kütüphanemiz 

using namespace std;

// Hesaplama fonksiyonlarımız
int toplama(int a, int b)
{
    return a + b;
}
int cikarma(int a, int b)
{
    return a - b;
}
int carpma(int a, int b)
{
    return a * b;
}
int bolme(int a, int b)
{
    return a * b; // Diğer fonksiyonların çıktısı doğru fakat burada bilerekten yanlış işlemi verdim
}

TEST(hesapMakinesi, toplama) // Unit Test fonksiyonumuz. Tüm testlerimizi "TEST" türü fonksiyonlarla yazarız
// hesapMakinesi; Test, sınıf ve bölme mantığı ile çalışır. Yani toplama işlemi hangi işlemler bütünüyle kullanılıyor, hesap makinesi. O zaman toplama işleminin test sınıfı hesap makinesi oluyor. Bu sınıflara "suite" denir.
// toplama; Bu ise o sınıfın içerisindeki test biriminin ismidir. Çıktıda gözlemleceğimiz üzere "hesapMakinesi.toplama" şeklinde göreceğiz
{
    EXPECT_EQ(toplama(2, 5), 7); // EXPECT_EQ, 1. parametresinde işlemi ve 2. parametresinde beklenen çıktı belirlenir ve işlem test edilir. Eğer işlemin sonucu 2. parametredekiyle farklı ise hata raporu verir. Hatasız geçer ise "İşlem başarılı" şeklinde ifade edilir
}
TEST(hesapMakinesi, cikarma)
{
    EXPECT_EQ(cikarma(5, 1), 4);
}
TEST(hesapMakinesi, carpma)
{
    EXPECT_EQ(cikarma(10, 6), 61); // Bilerek yanlış sonuç beklemesini ayarladım
}
TEST(hesapMakinesi, bolme)
{
    EXPECT_EQ(bolme(100, 20), 5);
}

int main(int argc, char* argv[])
{
    testing::InitGoogleTest(&argc, argv); // Tüm testleri çalıştırabilmek için ana sistemi başlatır. İstersek parametre vererekte testleri farklı çıktılara veya farklı modlarla yapabiliriz

    return RUN_ALL_TESTS(); // Tüm testleri çalıştırır
}

Derleme ve çalıştırma

g++ main.cpp -o main -lgtest

main

Çıktı ise;
Çıktıda gördüğümüz gibi yazdığımız testleri sonuçlarını, başarılı olanların ve olamayanların bir raporu bulunmaktadır.
gTest bizlere özel bazı parametreler sağlar. Böylelikle biz fazladan kod yazmadan gTest bizler için parametreye göre farklı işlemler yapabilir.
Çıktıyı belirli bir formatlı dosyaya isterkek

--gtest_output="format:ciktiDosyasi";

main --gtest_output="xml:cikti.xml" # Çıktı XML dosya formatında gözükür
main --gtest_output="json: cikti.json" # Çıktı Json formatında gözükür

Çıktılar;
main --gtest_repeat=tekrarEdilcekMiktar; Test "tekrarEdilcekMiktar" kadar tekrar eder.
        
main --gtest_break_on_failure; Test sürecinde hata çıktığı an programı kapatır.
